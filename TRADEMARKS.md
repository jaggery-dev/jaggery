# The Jaggery name and logo

The code is free to use under [Apache-2.0](LICENSE). The name **Jaggery** and the Jaggery logo aren't: the licence deliberately grants no trademark rights (section 6). This policy says how you may use them, so that when someone sees "Jaggery", they get the real thing, from the people who make it. It follows the spirit of the Rust and Mozilla trademark policies.

## Fine without asking

- **Talking about Jaggery**: articles, videos, talks, reviews, tutorials, comparisons, criticism.
- **Saying your thing works with Jaggery**: "an Open WebUI setup for Jaggery", "works with Jaggery's `ai.local`", "a Home Assistant integration for Jaggery".
- **Packaging unmodified Jaggery**: a distro package, a Homebrew formula, a NAS app-store entry, a Docker image built from an unmodified release, called Jaggery. Small changes needed only to make it build or install on that system (paths, service files) count as unmodified. Say who packaged it.
- **User groups and events**: "Jaggery users in Leeds", a Jaggery meetup, stickers and shirts you don't sell for profit.
- **Using the logo** to link to the project or to show something works with it, unaltered.

## Not without written permission

- **A modified version called Jaggery.** If you fork and change it, give it another name; you may say "based on Jaggery". This protects people from builds that look official but aren't.
- **Implying you're official** or endorsed: "Official Jaggery hosting", "Jaggery Pro", "Jaggery Cloud".
- **Jaggery in the name of your product, company or domain**, beyond saying it works with Jaggery.
- **Selling** goods with the name or logo.
- **Changing the logo**, or using something confusingly similar.

## Why this matters for a program like this

Jaggery runs on every computer in a house, finds the other devices and holds keys. A build that looks like Jaggery but isn't could do real harm. Official releases are signed, and Jaggery installs only updates with that signature. This policy covers the other half: the name.
